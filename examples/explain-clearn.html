The big idea

clearn is a Claude Code skill pack: its /learn and /explain commands hand your question to a dedicated subagent that fills a shared, self-contained HTML template into a diagram-rich explainer and opens it in your browser. The repo is small on purpose — a couple of instruction files, one template, one design doc.

1How a question becomes an explainer

Everything in clearn exists to serve one flow. You type a slash command in a Claude Code session; a skill — a markdown file of instructions — takes over, delegates the real work to a focused subagent, and the subagent produces a single HTML file and opens it. No server, no build step, nothing to host.

📌 The two altitudes

/learn and /explain share the same output format and design system; they differ only in altitude. /learn teaches a topic from the ground up (3–6 lesson steps, worked examples). /explain — what you're reading now — orients you over something that already exists: big picture, key pieces, how they fit. Lost in a thing (a repo, a file)? That's /explain. Want to understand a concept you don't know yet? That's /learn.

2The pieces (and where they live)

The tracked repo is deliberately tiny. Here is every file that matters and the job it does.

.claude/skills/learn/ and .claude/skills/explain/

Two skills, each a single SKILL.md. A skill is a named bundle of instructions Claude Code loads when you invoke it. Each file carries YAML front-matter (name, description) that registers the slash command, then a workflow: read the request, hand it to a subagent with an authoring contract, and save-and-open the result. They are near-twins that differ in altitude — learn teaches from first principles; explain maps what already exists and, when pointed at real code, insists the subagent read it first so the diagram reflects reality rather than a generic guess.

templates/learning-artifact.html — the design system

One self-contained HTML file that is both the reference design and a working demo: open it and every component is styled in light and dark mode. It is theme-aware (an auto default plus a toggle), responsive, and renders Mermaid diagrams with a graceful offline fallback — if the renderer can't load, the diagram source stays readable instead of vanishing. The subagent copies this file and replaces the content between its <!-- FILL: … --> markers, keeping the <style> and <script> blocks intact. This very page is that template, filled in.

docs/artifact-design.md — the authoring judgment

The template gives you the look; this doc gives you the judgment: write for someone who doesn't know this yet, motivate before mechanism, introduce every term before using it, find one mental model and return to it, pick the Mermaid diagram type that fits, and never put information only in a diagram. It also spells out the /learn-vs-/explain altitude split. It is the taste the skills point their subagents at.

README.md, LICENSE, .gitignore, and packaging

The README is the front door (what clearn is, quick start, what makes it different). LICENSE is MIT. .gitignore keeps generated explainers out of the repo — the default output folder out/ and any *.local.html are ignored, so your explainers never accidentally get committed.

✅ Install

./install.sh copies the skills into ~/.claude/skills and the shared design assets into ~/.claude/skills/clearn/assets/, so /learn and /explain work in any session. It refuses to overwrite a same-named skill it did not install, and --uninstall removes only what it created. Run from inside a clearn checkout, the skills also fall back to the in-repo templates/ and docs/ paths.

3The mental model: instructions + design system + author

If you remember one thing, remember the separation of concerns. clearn cleanly splits three jobs that could easily have been tangled into one prompt:

The skills are instructions — what to produce and how to run the workflow. The template plus the design doc are the design system — the shared look and the authoring taste, so every explainer feels like a sibling. The subagent is a focused author — the research and writing happen in a fresh context so your main session stays light. And the output is one portable HTML file — self-contained, so you can keep it, share it, or open it offline.

💡 Analogy

Think of a magazine. The skills are the editor's brief ("write a 5-minute orientation"), the template and design doc are the house style guide and layout, and the subagent is the writer assigned that one piece. clearn keeps those three roles separate so each can improve on its own — retune the taste in one doc, restyle everything in one template.

✅ Why the split matters to you

Want every explainer to look different? Edit the template. Want them to read differently (more rigor, gentler ramp)? Edit docs/artifact-design.md. Want a new kind of command? Add a skill. The boundaries are where you make changes.

Glossary

Skill
A named bundle of instructions (here, a single SKILL.md with YAML front-matter) that Claude Code loads to perform a task.
Slash command
How you invoke a skill in a session — typing /learn or /explain followed by your topic.
Subagent / delegation
A separate, focused Claude agent the skill hands the research and authoring to, keeping your main session light and the work concentrated.
Self-contained artifact
One HTML file with all its CSS and JS inlined — no server, no external assets to fetch — so it works offline and travels as a single file.
Mermaid
A library that renders diagrams from a plain-text description; clearn embeds it with an offline fallback that shows the diagram source if it can't load.
Design system
The shared look and authoring rules — the template plus docs/artifact-design.md — that make every explainer feel like part of one family.

Check your understanding

You want every future explainer to use a warmer color palette. Which file do you touch?

templates/learning-artifact.html — the design system owns the look. The skills and the subagent don't hardcode styling; they fill the template's regions, so a change there flows to every explainer.

Why hand the work to a subagent instead of writing the HTML in the main session?

Separation of concerns and focus: the research and authoring run in a fresh context so your main session stays light, and the subagent can concentrate its full effort on one explainer.

What's the real difference between /learn and /explain?

Altitude, not format. They share the template and design system. /learn teaches a concept from first principles; /explain maps something that already exists so you can navigate it.
