How a hash map works

The data structure behind "look something up instantly by its name" — and why it's usually O(1).

Difficulty: Beginner Prerequisites: arrays, a little code ~8 min read

The big idea

A hash map turns a key (like a word) into an array position using a function, so it can jump straight to the value instead of searching. That jump is what makes lookups feel instant.

What we'll build up

1The problem: searching is slow

Imagine a list of 10,000 names and phone numbers. To find one number, you check names one by one until you hit a match. On average that's 5,000 checks. Double the list and you double the work — this is linear time, written O(n).

💡 Analogy

It's like finding a friend's house by knocking on every door down the street. A hash map is knowing the house number and walking straight to it.

2The trick: turn a key into an index

Arrays are fast when you know the index: a[42] is instant. A hash map adds one idea — a hash function that turns any key into a number we can use as an index.

Now storing and finding both skip the search: hash the key, go to that slot.

slot = hash(key) % number_of_slots
slots[slot] = value        # store
value = slots[hash(key) % n]   # look up

3Collisions, and how to survive them

Two different keys can hash to the same slot — a collision. The common fix is chaining: each slot holds a small list, and colliding keys queue up there.

📌 Note

Good hash functions spread keys evenly, so chains stay short. If everything collided into one slot, you'd be back to slow linear search.

4Why it's usually O(1)

If chains stay short (the map resizes as it fills), each lookup does a constant amount of work no matter how many items there are — O(1) on average.

⚠️ Watch out

It's average-case O(1). A bad hash function or an adversary feeding colliding keys can degrade it to O(n). Real libraries defend against this.

✅ Rule of thumb

Reach for a hash map whenever you think "I need to look this up by a name/id fast" and you don't need sorted order.

Glossary

Key
The thing you look up by (a name, an id).
Hash function
Turns a key into a number used as an array index.
Collision
Two keys landing in the same slot.
Chaining
Storing colliding entries in a small per-slot list.
O(1) / O(n)
"Constant" vs "grows with size" — how work scales with item count.

Check your understanding

Why is a hash map faster than scanning a list?

It computes the location from the key, so it jumps straight there instead of checking items one by one.

What breaks the O(1) guarantee?

Many collisions — from a poor hash function or too many items without resizing — which lengthen the per-slot chains back toward linear search.
